# Agent Note: 餐厅设计试用采用按需加载和项目独立存储

Status: implemented

[English](2026-10-27-restaurant-design-pilot.md) | 中文

## 问题

提供的餐厅 HTML 已有可用的 SVG 和 Three.js 编辑器，但浏览器状态缺少建筑底图，本地历史也不能表示助手修改。源数据还含有重叠与重复几何，拒绝所有继承重叠会阻止常规布置操作。

## 决策

[本地餐厅工作台](../../../../restaurant-design/README.zh.md) 通过显式 Harness overlay 挂载项目提供者、工具消费者和浏览器消费者。默认应用组合与模型保持不变。单个同步文件写入者拥有完整项目和已接受的版本历史；鼠标和工具编辑均携带预期版本，通过该写入者执行。持久化失败时既不发布版本，也不发布历史。

写入者拒绝新增或加重的重叠，将导入问题保留为基线。显式组合允许已有内部重叠，并支持刚性平移；浏览器整状态替换不能通过独立移动、旋转、改尺寸或删除成员绕过检查。撤销和重做创建单调递增的版本。

提供的文档在禁用网络的不透明来源隔离框架中运行。可信父页面检查消息所属框架，仅通过已认证 Connection 路由代理固定餐厅操作。导入文档和模型工具参数都无法获得任意 Host 访问能力。

工作台将现有 Harness 对话、可编辑平面和只读 Three.js 场景放在同一页。替换工具使用消息提交时记录的选中对象和版本。预览仅保存在内存。可信查看器外层处理确认，并按候选的基础版本提交已经校验的布置。撤销从同一历史恢复原构件及组合成员。

## 考虑过的替代方案

### 构建独立助手应用

独立应用会在餐厅流程得到验证前重复实现模型路由、会话历史和工具执行。按需加载的 overlay 可以复用这些能力，而无需增加受支持的 Node 应用启动入口。

### 仅同步 localStorage 和截图

浏览器本地历史会丢失助手修改，截图也缺少可编辑几何。完整项目和共享写入者保留可测量的修改与统一撤销历史。

### 将每个导入重叠都当作新错误

提供的方案已有对象重叠。将候选问题与已接受布置比较，可以允许修正，同时拒绝新增冲突和既有冲突恶化。

## 影响

试用支持提供的查看器，每个项目限一个进程。四人桌模板检查候选餐椅的拉出空间，其他家具使用占地检查。实测房间范围、消防审查和施工图需要额外资料。源查看器作为工作目录资源保留，仓库测试夹具使用合成方案。

## 验证

局部测试覆盖源数据提取、持久化失败、刚性组合、基线比较、版本冲突、选择竞态、隔离框架、已接受状态回滚，以及真实 Loader 工具注册和卸载。实际 Web profile 演示组合移动 300 mm、Three.js 显示、刷新、共享撤销、旧版本拒绝和完整项目导出。真实模型完成移动和撤销两轮对话；[无密钥场景](../../../../snapshots/session/restaurant-layout/snapshot.yml) 使用合成几何与独立文件预期固定这些工具操作。
