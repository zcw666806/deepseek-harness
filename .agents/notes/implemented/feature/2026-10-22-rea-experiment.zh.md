# Agent Note: 会话级 REA 实验

Status: implemented

[English](2026-10-22-rea-experiment.md) | 中文

## 问题

用户需要从 Web 助手试用 REA 声明的全部工具，无需逐个手改 agent preset。REA 拥有可变的分析目标与本地进程，因此多个聊天共享一条 Host 连接会混淆独立工作。恢复时读取全局开关，也可能为已有对话添加从未选择的工具，或移除其历史仍在引用的工具。

## 决策

Host 拥有的 `rea-experiment` 设置命名空间默认关闭。插件设置卡同时暂存 `enabled` 与 stdio 启动配置 `command`、`args`、`toolCallTimeoutMs`。保存只校验并持久化设置，不启动服务器。高级字段承载非密钥的启动配置；凭据不得放入命令或参数。关闭只保存开关，并保留已存启动配置供以后重新使用。

新的顶层 Web 会话在组装 agent 时采样该设置。启用的会话以 `serverName: rea` 开启独立的 `dsh-mcp-client` 实例，并在发现成功后、首次请求前将所选启动配置记录到 `rea-experiment/selected`。服务器声明的每个工具都按现有 MCP 命名与执行规则加入该会话的工具注册表。初始连接或发现失败会拒绝会话准备，而不会发布缺少工具的聊天。

恢复与 fork 使用会话记录的启动配置，而非当前设置。没有选择记录的会话保持关闭。更改或关闭全局设置只影响新建的顶层会话，不停止或重配已选择 REA 的会话。结束该会话会释放其连接。REA 的浏览器与分析引擎仍是本机前置条件；工具发现成功不代表这些依赖可用。

该实验组装交互工具，不拥有定时采集、数据源授权流程、增量同步或知识索引。它贡献固定的 Host 提示词分节 `rea-external-content`：捕获内容是数据而非指令，访问与操作需要用户授权。preset 的完整 persona 按现有提示词规则抑制该分节；REA 不覆盖用户选择的完整提示词。MCP 桥接不投影服务器 instructions 或结果顶层 `_meta`，因此所贡献的策略不依赖 REA 的目标内容来源标记。

## 考虑过的替代方案

**Host 全局共享一条 REA 连接。** 拒绝，因为 REA 的活动目标与进程生命周期属于独立分析会话。独立连接避免一个聊天的目标选择与释放改变另一个聊天。

**每次恢复会话时读取当前开关。** 拒绝，因为设置变更会静默改变已有对话的能力。持久选择让恢复与 fork 使用同一启动配置，并使没有该记录的会话保持关闭。

**额外维护 REA 工具允许列表。** 本实验拒绝此方案，因为用户选择的是服务器声明的全部工具。现有工具执行器与配置的审批策略仍拥有调用决策；不再把工具过滤作为第二次启用决定。

**保存设置时连接。** 拒绝，因为共享探测成功无法证明后续会话的独立服务器或所需引擎可用。保存负责配置，会话准备负责连接是否成功。

## 后果

默认部署不启动 REA 进程。每个选择启用的会话承担独立的启动与进程成本，服务器声明的全部 schema 为该会话的模型请求增加 token。启动错误在创建或恢复该会话时出现；保存卡片不能证明运行时已就绪。

选择启用的会话在全局开关关闭后仍保留启动配置，恢复或 fork 时也一样。停止已有工作的 REA 需要结束对应会话。持久事件没有凭据字段，但会将所选可执行文件与参数纳入会话数据；用户必须确保这些值不含凭据。

## 验证

无需密钥的 [Web 录制会话场景](../../../../apps/web/tests/rea-experiment.snapshot.ts)通过已交付的会话 API，对场景自有的 stdio 服务器创建会话。其记录固定所选启动配置、服务器声明的完整工具目录、外部内容提示词与已执行的工具结果；关闭设置会使后续会话不含 REA，同时保留已选择会话的工具。该场景使用可移植的仅含 persona 的 preset，不验证真实 REA 引擎或远程数据访问。
