# Agent Note: 工作区拥有漫画项目和原画

Status: implemented

[English](2026-11-12-workspace-comic-projects.md) | 中文

## 问题

短篇漫画需要反复修改画格、原画、对白和阅读顺序。作者需要在其他会话中打开项目，把指定图层交给绘画应用修订，并交付别人能继续编辑的工程。阅读版 PNG 只包含成稿像素。

## 决策

[漫画制作服务](../../../../packages/comic/comic-production/README.zh.md)在工作区保存项目标识和已提交的修订。会话可访问所属工作区的项目。宿主操作在发布修改前核对会话归属，并比较提交的修订号与已保存的修订号。

页面版式和对白是结构化项目数据。原画修订引用留存的原始 PNG 字节。[漫画制作视图](../../../../packages/client/ui-comic-production/README.zh.md)按原始尺寸导出单层，接受相同尺寸的 PNG 作为新稿。选择原画修订与编辑画格几何或对白是独立操作。

带版本的项目包包含版式、对白、原画历史及其引用的 PNG 数据。导入时创建独立项目。浏览器根据采用的原画和对白渲染页面 PNG。

## 考虑的其他方案

**把项目绑定到会话。** 一部漫画可能在制作过程中使用多个会话。项目归工作区后，这些会话可以打开同一份已保存工程。

**用规范化后的聊天附件保存母版。** [附件流程](../../../../docs/subsystems/attachment.zh.md)可以缩放或重新编码图像。图层修订需要原始尺寸和源文件字节。

**在浏览器实现完整绘画工具。** 交换单层 PNG 允许作者在外部绘画，并在工作台继续编辑页面版式和对白。绘画应用的原生文档由作者保存。

## 后果

作者可以独立交换修订后的图层，并将项目包转移到其他工作区。首个交换格式支持 PNG 图层。完整的原生绘画文档、生图和印刷输出需要单独集成。并行编辑时需要将过期修订与当前保存的项目对照处理。
