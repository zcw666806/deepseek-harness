# Agent Note: 安全工作流控制、持久批次与片段编辑

Status: implemented

[English](2026-11-03-production-workflow-controls-and-durable-batches.md) | 中文

## Problem

制作控制必须区分已保存配置、已启用目标和运行中的引擎。浏览器断连不能丢失付费批次的归属，Host 重启也不能静默重提结果未知的请求。编辑已采纳片段必须保留其源媒体，以及先前导出影片使用的设置。

## Decision

[工作流编辑器](../../../../packages/video/video-comfyui/src/workflows.ts) 通过带修订号的设置暴露服务地址和可迁移 API 工作流。它排除请求头值，保留宿主凭据及运行环境绑定，并拒绝不安全的工作流凭据和机器路径。保存会验证候选配置、检查设置修订号，并以禁用状态持久保存。显式启用只注册目标，不启动引擎。原生黑帧起步模板明确标为非 AI 生成的诊断，不代表模型可用或输出质量已验证。

[能力恢复预览](../../../../packages/capability/capability-manager/src/index.ts) 验证清单结构并检查已安装提供方，不恢复设置、准备环境或启动运行环境。引擎身份、版本及恢复支持决定兼容性。导入配置保持 `pending-validation`，直到提供方在显式恢复时准入。兼容项仍可能缺少前提条件或处于停机状态；兼容既不等于配置已验证，也不等于就绪。

[批次所有者](../../../../packages/video/video-production/src/tasks.ts) 为每个项目 Session 生命周期持久保存一个描述记录，并独立于浏览器运行待处理镜头。记录冻结生成路由、工作流修订、镜头输入和有序参考图。Host 在生成前先持久保存镜头的 `running` 检查点。恢复把未完成检查点归为 `uncertain`，不会重放它。继续批次会重新验证项目归属、冻结输入、目标修订及已记录的完成结果；只有 `pending` 镜头可以提交。暂停会在当前镜头完成后停止准入。暂停请求或本地关闭不能证明远端请求已经停止。

批次描述记录和执行器具有不同生命周期。持久保存现有 jobs 回调或闭包不能让其可执行状态恢复；制作服务拥有明确的数据及恢复规则。当 Host 无法证明第一次请求的结果时，这个选择明确倾向于人工核查，而不是自动发起第二次付费请求。取消会在当前镜头结束后停止待处理工作；卸载会中止提供方工作，并等待服务的执行器及持久写入结束。

片段编辑采用[非破坏性数据](../../../../packages/video/video-production/src/editing.ts)：相对源媒体的裁剪、音量和字幕不改变已采纳附件。字幕时间相对于裁剪后的片段。渲染器把字幕文本写入私有 UTF-8 文件，并使用带 `expansion=none` 的固定 `textfile` 滤镜；用户文本不会成为滤镜表达式。导出会同时捕获 `clipEdits` 和源版本身份，后续项目编辑不会改变已记录的影片输入。

这些决定细化了 [Session 所有的制作工作区](2026-10-27-video-production-workspace.zh.md)以及[托管能力与可迁移性](2026-10-29-managed-capabilities-and-project-portability.zh.md)。两份记录继续保持有效，因为其 Session 权威、媒体归属、运行环境隔离及迁移理由仍有独立价值。

对话外壳将对话宽度拖柄限定在 Chat 中。其他已注册 View 保留自己的内容布局和控件，不会被对话拖拽区域截获指针输入。

## Alternatives considered

**保存时启用导入或编辑的工作流。** 配置编辑会获得执行副作用，并可能在操作者决定使用之前启动绑定到机器的运行环境。保存和启用保持独立。

**把兼容的恢复预览视为已验证且就绪。** 提供方配置准入和运行环境前提条件是独立检查。预览保留这些未确定事实，不授予执行权威。

**在浏览器回调中保留批次进度，或重启后重放运行中检查点。** 浏览器生命周期不能拥有持久工作，未完成的本地记录也不能证明付费远端提交没有发生。明确持久保存的检查点支持保守恢复，无需序列化闭包。

**覆盖已采纳媒体，或把字幕文本插入渲染滤镜。** 覆盖会丢失已采纳片段的原始字节。滤镜插值会使字幕文本改变渲染滤镜的语法。不可变源媒体、捕获的编辑记录和字面字幕文件保留可复现性，并约束渲染器输入。

## Consequences

作者可以编辑工作流、检查恢复要求、暂停批次并调整导出片段，而不混淆配置、执行和媒体归属。不确定的尝试需要检查提供方并由用户明确判断；自动恢复无法保证远端恰好执行一次。批次保留待处理工作，不承诺恢复任意任务或回调。渲染仍需要已批准的本地 FFmpeg 和 FFprobe。

## Verification

工作流 Loader 测试覆盖安全读取、设置修订、并发保存冲突、独立设置所有者、显式离线启用和诊断模板验证。Host 批次及制作测试覆盖持久检查点、恢复、暂停及继续准入和项目状态。能力预览测试覆盖兼容性及待验证配置；控制器测试覆盖相应用户操作。渲染器测试覆盖裁剪、音量、字面字幕和捕获的导出编辑。Host 严格类型检查验证生成的 Remote 输入及类型化失败。

浏览器验收覆盖配置预览、禁用保存、不启动引擎的明确启用、后台制作期间关闭页面、保留检查点，以及镜头边界的暂停、继续和取消。[真实成片场景](../../../../apps/web/tests/video-film-export.e2e.ts)导出带中文字幕的已裁切合成片段，保留生成历史，探测 H.264/AAC 输出，并在渲染器失败后保留成功成片。项目包测试保留片段编辑。导入在媒体准入前拒绝 `clipEdits` 与 `shotVersionIds` 数量不符或字幕数量超限的项目。

通过当前网关观察到的真实 `grok-imagine-video-1.5` 和 `grok-imagine-video` 请求均返回 HTTP 503，内容为 `No eligible Grok media accounts`，尽管该网关的模型目录列出了两者。没有生成视频。成功的真实提供方生成和 AI 输出质量仍是覆盖缺口；合成媒体和原生诊断不能填补这个缺口。
