# Agent Note: 用户批准经审查的插件产物

Status: implemented

[English](2026-10-26-plugin-review-workflow.md) | 中文

## Problem

为助手选择能力，可能让 agent（智能体）在用户看到访问要求或部署文件审查之前，就安装或执行第三方代码。一项安装请求并未明确用户需要信任的产物、依赖、脚本和配置改动。

## Decision

项目的[插件审查 skill](../../../skills/dsh-plugin-review/SKILL.md) 优先复用已有可调用能力，要求先提交审查报告，再由用户明确批准，才能安装或执行新增插件代码。自动发现保持启用。报告明确产物、依赖、目标、拟执行动作、证据和未解决风险；同一对象和动作的批准持续有效，实质变更则需要更新审查并获得批准。

只读获取和检查先于批准。依赖安装、构建脚本、候选插件自带扫描器、本地 MCP 启动，以及通过配置或动态插件激活代码，都不能绕过这一要求。现有可调用工具仍可在用户当前授权范围内使用，无需重复安装审查。

[Profile 组合包决策](../architecture/2026-08-05-profile-plugin-bundles.zh.md) 继续负责组合与安装机制，[pnpm 决策](../../../../docs/development.zh.md) 继续负责仓库包管理器和构建脚本策略。本 skill 增加 agent 工作流程，不取代这些决策，也不修改安装器。

## Alternatives considered

**先禁用脚本再安装。** 这仍然在用户要求的审查和批准之前安装代码，而且不能阻止插件加载后的执行。

**把漏洞扫描无告警当作批准。** 已知漏洞报告既不能授权执行，也不能证明部署代码中没有恶意行为。

**每次使用已有工具都要求确认。** 重复确认无法审查新增代码，还会妨碍会话使用已有且获授权的能力。

## Consequences

用户可以批准具体产物和执行范围，agent 可以继续执行未变化且已经批准的工作，无需再次确认。证据不完整的部分保持可见，不会被表述为插件没有后门。

本 skill 约束 agent 行为，不增加运行时安装阻断，也不隔离已加载的插件代码。未加载该 skill 的环境保持原有行为。运行时强制执行需要单独的实现决策。
